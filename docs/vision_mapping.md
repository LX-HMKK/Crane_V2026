# Crane 视觉模块映射规则

## 豆子 → 目标数字

取货区 ①–③ 号位通过豆子相机识别豆子种类，内部映射为要搬运到的数字：

| 豆子种类 | 目标数字 | 放置区货箱 |
|----------|----------|------------|
| 黄豆     | 1        | 贴有数字 1 |
| 绿豆     | 2        | 贴有数字 2 |
| 白芸豆   | 3        | 贴有数字 3 |

配置位置：`configs/vision.yaml` 的 `mapping.bean_to_digit`。

## 数字 → 放置区

数字相机识别放置区 ④–⑧ 号位侧面的数字 1–5，再反向查表：

- 数字 1 在哪个放置区 → 黄豆该去的位置
- 数字 2 在哪个放置区 → 绿豆该去的位置
- 数字 3 在哪个放置区 → 白芸豆该去的位置

数字 4、5 所在货箱为空箱，识别结果可显示但不参与任务生成。

## 辅助线分区规则

辅助线位置保存在 `configs/vision.yaml` 的 `lines` 字段，可在 `scripts/main_arm64.py --ui` 中拖动调整。

### 豆子相机（取货位 ①–③）

两条竖线 `bean.left_x`、`bean.right_x` 将画面分成三列：

| 检测框中心 x 范围 | 取货位 |
|-------------------|--------|
| `cx < left_x`    | ①      |
| `left_x <= cx < right_x` | ② |
| `cx >= right_x`  | ③      |

### 数字相机（放置区 ④–⑧）

5 个放置篮在画面中基本排成一排，因此用 **4 条竖线** `digit.x1..x4` 从左到右划分 5 个区域：

| 位置 | 中心条件 | 放置区 |
|------|----------|--------|
| 最左 | `cx < x1` | ④ |
| 左二 | `x1 <= cx < x2` | ⑤ |
| 中间 | `x2 <= cx < x3` | ⑥ |
| 右二 | `x3 <= cx < x4` | ⑦ |
| 最右 | `cx >= x4` | ⑧ |

> 严格 `<` 的边界语义：检测框中心恰好落在竖线上时，归入右侧区域。若实际场地方向相反，只需在 UI 中调整 `x1..x4`，代码不做方向硬编码。

## 缺失与重试策略

1. 连续采集 `scan.frames` 帧（默认 5）。
2. 每帧分别对豆子相机和数字相机做推理。
3. 按辅助线把每个检测框归入对应区域。
4. 每个区域保留**置信度最高**的检测结果。
5. 扫描结束后：
   - 若 3 个取货位颜色分别为 01/02/03 且不重复、放置区 4–8 的数字为 01–05 且不重复 → 生成完整结果帧。
   - 任一区域缺失或出现重复 → 记录原因，主程序重试；仍失败则不发送残缺帧。

## 输出帧

视觉 → 下位机：

```text
A5 5A C1 C2 C3 N4 N5 N6 N7 N8 0D 0A
```

| 字段 | 长度 | 含义 |
|------|------|------|
| `A5 5A` | 2 字节 | 固定帧头 |
| `C1` | 1 字节 | 取货区 1 的豆子颜色（01=黄豆，02=绿豆，03=白芸豆） |
| `C2` | 1 字节 | 取货区 2 的豆子颜色 |
| `C3` | 1 字节 | 取货区 3 的豆子颜色 |
| `N4` | 1 字节 | 放置区 4 上的数字 |
| `N5` | 1 字节 | 放置区 5 上的数字 |
| `N6` | 1 字节 | 放置区 6 上的数字 |
| `N7` | 1 字节 | 放置区 7 上的数字 |
| `N8` | 1 字节 | 放置区 8 上的数字 |
| `0D 0A` | 2 字节 | 固定帧尾 |

约束：

- `C1-C3` 必须是 `01、02、03` 各一次。
- `N4-N8` 必须是 `01-05` 各一次。
- 发送的是单字节数值，不是 ASCII 字符。
